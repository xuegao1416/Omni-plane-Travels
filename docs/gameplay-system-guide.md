# 玩法系统指南

世界漫游指南的玩法模块共享同一个声明式结算内核。模块只描述条件、消耗、效果、奖励和事件，运行时由内核以原子事务执行；模块之间不直接修改彼此的私有状态。

## 统一协议

模块运行时状态位于 `GameState` 的模块命名空间中。一次结算使用 `GameplayTransaction`：

- `conditions`：状态或事件条件，支持 `all`、`any`、`not` 与比较运算；
- `costs`：从指定路径扣除点数、资源、货币或时间；
- `effects`：设置、增减、追加、移除、发出事件或安排延迟事件；
- `rewards`：条件成功后追加的一组效果；
- `events`：供其他模块和叙事层消费的结构化事件。

每次事务都会产生变更日志。失败时状态保持不变，旧存档通过玩法运行时迁移自动补齐缺失字段。

已应用的事务可以按日志撤销。撤销前会核对每个目标路径仍然等于该事务写入后的值；若后续玩法已经改过同一路径，撤销会被拒绝，避免用旧快照覆盖新进度。撤销成功后，对应事件、历史和计划事件会一并清理，原日志保留并标记为 `reverted`。

## 可插拔模块

| 模块 | 主要状态 | 典型联动 |
| --- | --- | --- |
| 数值属性 | `attrA`、`attrB`、`dim1`-`dim6` 与特色属性 | 条件、修正器、奖励 |
| 成长体系 | 等级/段位与经验 | 发放属性点、天赋点和技能点 |
| 职业与能力 | 职业阶位、能力点、熟练度、冷却和装备 | 检定修正、自由技能与战斗行动 |
| 骰子检定 | DC、属性加值、优势/劣势和结果等级 | 触发事件与奖励 |
| 生存资源 | 资源、配方、周期消耗和制作 | 时间、属性惩罚、技能解锁 |
| 经营资产 | 资产、员工、市场和周期结算 | 资源产出、资金与升级 |
| 图形化战斗 | 阵容、行动、状态、冷却、道具和战报 | 职业能力、事件选择与正文承接 |

模块可以任意组合；成长体系自动依赖数值属性，其余依赖由世界配置声明。

### 数值与成长

数值模块区分基础值、派生值和修正器。修正器支持固定值、百分比、永久和按 tick 到期；派生属性会在基础值或修正器变化后重新计算。成长模块负责等级/段位经验、点数发放和显式突破，突破可以同时声明条件、消耗与奖励。

### 职业、能力与检定

`AbilityDefinition` 是所有能力的唯一机械协议。先天天赋、职业能力、自由技能、剧情动态技能以及宠物/召唤能力只在获得来源上不同，不再各自维护一套消耗、冷却、目标、倍率、状态和被动字段。AI 生成动态技能时只能提交类型、目标、稀有度与叙事描述；本地配平器生成最终数值，玩家确认后才写入能力库。

职业包使用 schema v2。内置“经典幻想职业典藏”和“东方幻想职业典藏”，分别提供战士、法师、游侠、盗贼、牧师、圣骑士，以及剑客、刀客、枪客、拳师、医者、奇门。每个职业包含四阶、至少八个机械节点、两条互斥专精和一个终极能力；职业典藏可复制、修改、导入导出和 AI 修订。世界只保存职业包引用，未启用职业模块时不会显示职业创建步骤，也不会向模型注入职业提示词。

能力节点支持前置、互斥、多级、熟练度、装备槽和主动使用。图形化能力树读取节点坐标，不维护第二份玩法状态。骰子检定统一输出大失败、失败、部分成功、成功和大成功，支持优势/劣势、属性与能力修正，并将结果写成结构化事件供其他模块消费。

### 生存与经营

生存模块支持采集、周期消耗、配方解锁、制作时间和临时状态。经营模块支持资产购置/升级、员工安排、库存、生产链、维护费、市场倍率和周期结算。

## 图形化战斗

战斗是可选的独立玩法域，不是六个官方世界的强制步骤。世界挂载战斗模块后，变量管线只会在正文已经发生明确敌对行动时提出 `CombatEncounterProposal`；类型化事件卡、规则工作流或玩家手动入口也可以发起遭遇。提案只包含敌友身份、遭遇语境和弱小/匹敌/危险/首领/压倒性威胁档位，生命与伤害等数值由本地按队伍强度生成。

战斗流程：

1. 正文或工作流确认冲突，弹出“迎战、尝试脱离、叙事处理”事件卡。
2. 选择迎战后进入独立战场，从玩家、明确友方、宠物与召唤物中选择最多四名单位。
3. 每个单位每轮执行一次攻击、技能、道具、防御或逃跑；敌方与自动友方由进攻、均衡、防守、支援四种本地策略控制。
4. 命中、伤害、防御、治疗、暴击、状态、冷却和资源消耗按随机种子确定性结算。不同世界的属性先归一化到统一尺度，避免 0–20 与 0–100 数值失衡。
5. 战斗结果先保存，再把不可改写的结构化战报交给主模型生成一次承接正文。空回、过滤或断网时可重试正文，不会重复奖励或消耗。

每方最多四个单位；更多敌人会作为群体单位或分波次出现。临时怪物只存在于当前遭遇，不会强行污染 NPC 档案。道具只有在具备受控战斗用途时才产生机械效果，无法识别的旧物品仍是叙事物品。

### 风险、恢复与封存

启用战斗模块后，创建旅程最终确认页会要求选择不可中途修改的战斗风险：

- 普通：生命归零为失去战力并可产生伤势，允许恢复战前检查点重打；
- 困难：玩家和同伴可能重伤或死亡，允许恢复战前检查点重打；
- 炼狱：允许死亡，禁止战斗重打和历史回滚；玩家死亡后存档封存，但仍可查看、导出和回顾。

开战前检查点覆盖变量、消息、记忆、世界推演和模块状态。战斗行动、道具扣除、奖励和终局结算均使用幂等 ID；刷新或关闭页面后重新进入存档会恢复未完成的战斗。战斗和待承接阶段会暂停普通消息、世界 tick 与记忆写入，避免后台状态漂移。

## 自定义模块

自定义模块只能使用公开能力目录，状态必须写入自己的命名空间，权限固定为 `own-state-only`。Agent 输出的是 JSON 模块定义，不是可执行代码；本地校验器会拒绝脚本、网络、文件和未知路径。

推荐流程：

1. 在自定义模块工作区选择目标世界并描述玩法目标。
2. Agent 逐轮确认目标、触发、输入、规则和展示方式。
3. 草案通过校验后保存并绑定到世界。
4. 运行时在 `onGameStart`、`onTurnEnd`、`onTick`、`onChoice` 或 `onButton` 生命周期执行。

## 存档兼容

新开局和读档都会运行玩法迁移。迁移只新增缺失的模块状态，不覆盖已有玩家数据；未知模块字段保留，便于第三方模块升级。

旧世界在构建时会保留已有配置，并为新增字段使用兼容默认值。旧职业包、天赋、技能、战斗历史和存档执行只增不删迁移；旧存档默认普通风险，首次加载时补齐统一玩法运行时、能力状态、修正器、制作/经营状态和战斗会话，不会重置玩家已有属性、资源或进度。未启用职业或战斗模块的旧世界保持原样。

## 样板世界

`public/examples/japanese-rpg-world.json` 是可直接导入的垂直样板，包含成长点数、分支能力树、互斥路线、觉醒、技能熟练度、骰子检定以及“回响守卫”战斗遭遇。它用于验证共享协议，不是内核里的日式 RPG 特判。

## 模块完成标准

新增或重构模块必须同时提供：数据模型、配置编辑器、运行时状态、确定性结算、AI 提示词契约、跨模块协议、游戏内面板、文本降级、存档迁移、示例配置、使用说明和定向测试。
